# AI 협업 로그
> AI가 틀렸거나, 내가 방향을 고쳐준 순간을 기록합니다. 3~5건이면 충분합니다.
> 이 문서가 크래프톤 AI 역량평가(문제 정의, AI에 일 맡기기, 오류 수정, 결과 검증)와 가장 직접적으로 연결됩니다.

## 사례 1 (날짜: 2026-10-15)
- 내가 시킨 것(지시문 요약): "오늘 마무리" → 하루 작업을 git commit
- AI가 낸 결과: 첫 커밋(2786cac)을 만들고 .env·원본 데이터·API 키가 빠졌는지만 확인한 뒤 "완료"라고 보고함
- 내가 발견한 문제: git 사용자 이름·이메일이 설정되지 않은 상태였는데 확인 없이 커밋함. git이 Mac 계정 이름과 컴퓨터 이름으로 만든 가짜 주소(…@…MacBookAir.local)를 작성자로 자동 기록했고, AI가 조용한 모드(-q)로 커밋해서 경고도 보이지 않음
- 어떻게 발견했나(검증 방법): 커밋 해시 설명을 듣다가 "이름과 이메일이 설정 안 되지 않았나?" 의심 → git config와 git log의 작성자를 확인해 사실로 확인
- 수정 지시: 이름은 Sungsik Choo, 이메일은 실제 주소가 공개되지 않도록 GitHub 비공개(noreply) 주소로, 이 컴퓨터 전체(--global)에 설정한 뒤 첫 커밋의 작성자 정보 수정
- 최종 결과: git config --global에 이름·이메일을 설정하고, 아직 push 전이었으므로 첫 커밋을 amend(--reset-author)해 작성자를 바꿈. 커밋 내용은 그대로이고 커밋 번호만 2786cac에서 새 번호로 바뀜
- 배운 점(1줄): AI가 "민감 정보 없음"까지 점검해도 작성자처럼 바로 눈에 띄지 않는 정보는 놓칠 수 있으니, 첫 커밋 전에는 git config를 직접 확인한다

## 사례 2 (날짜: 2026-10-16)
- 내가 시킨 것: 핵심 수치를 원본과 대조하는 확인용 출력 작성
- AI가 낸 결과: 검증은 모두 통과. 그 과정에서 duration이 50분 이상(최대 500분)인 매치 189건을 "비정상적으로 긴 매치"로 보고하고 평균 대신 중앙값을 쓰자고 제안함. 나는 이를 받아들여 50분 이상 매치를 제외하기로 결정했고, AI는 제외 후 비피크 스쿼드에서 선호 자리 맵의 봇 비율이 크게 바뀐다고 보고함(W4 미라마 39.8 → 22.9%)
- 내가 발견한 문제: 블루존 1~9페이즈 시간의 합으로 매치 최대 시간이 정해져 있는데 50분짜리 경기가 나올 수 없음 → AI가 duration을 "경기 시간"으로 잘못 해석함
- 어떻게 발견했나(검증 방법): 게임 규칙(도메인 지식)과 숫자가 맞지 않는다는 점을 질문 → AI가 원본에서 duration과 참가자별 생존 시간을 비교. 50분 이상 189건 모두 duration = 마지막 봇의 생존 시간이었고, 사람 최대 생존 시간은 최대 29.0분(정상 매치 표본 150건과 같음). 사람이 경기를 끝낸 뒤 봇만 남아 매치가 평균 37분 더 열려 있던 것
- 수정 지시: 50분 이상 제외를 취소하고 사람 0명 매치만 제외, 경기 시간은 duration 대신 사람 최대 생존 시간 사용
- 최종 결과: 3,484건 재조회로 사람 최대 생존 시간 저장(오류 0), 분석 대상 3,228건(사람 0명 3건 제외). 원본 대조 검증 통과. 같은 잘못된 필드 때문에 AI가 앞서 "파라모는 경기 시간이 태이고와 비슷(29.7분)"이라고 했던 결론도 틀렸음이 드러나 정정(사람 기준 20.7분 vs 26.8분)
- 배운 점(1줄): API 필드 이름(duration)을 그대로 믿지 말고 게임 규칙과 맞는지 확인해야 하며, "이상치 제외"는 그 값이 왜 이상한지 원인을 확인한 뒤에 결정한다
